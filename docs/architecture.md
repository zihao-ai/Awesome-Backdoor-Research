# Repository architecture

Awesome Backdoor Research is a curated research catalog. Readers browse one generated README; contributors maintain structured records and a small set of editorial documents.

## Sources and outputs

`data/taxonomy.json` determines navigation, category order, stable anchors, and every paper table. Its hierarchy has 12 areas and 39 subcategories, with Surveys first. Add or rename classifications there; do not create parallel handwritten lists of paper entries.

`data/papers/YYYY.json` stores each paper once. Its `topics` array contains one or more leaf IDs, allowing the same record to appear in multiple appropriate tables. The filename year must match each record's displayed publication year. `types` is an array of Attack, Defense, Analysis, Application, Survey, Benchmark, or Dataset. Survey records belong in survey subcategories; benchmark and dataset papers belong in their subject areas.

`data/resources.json` keeps tutorials/courses, workshops, and toolboxes separate from paper records. The README template supplies fixed prose and exactly five generated slots: `AREA_NAVIGATION`, `PAPERS`, `TUTORIALS`, `WORKSHOPS`, and `TOOLBOXES`.

```text
JSON records + JSON Schemas ── validate ──┐
                                        ├── build ── README.md ── local preview
README template + icon assets ───────────┘
```

README is the only generated file committed to Git. HTML previews and link reports are local outputs. Topic pages, separate year indexes, databases, and a website are unnecessary at the current scale. If the catalog becomes unwieldy, additional views can be generated from the same data without duplicating records.

## Contracts

- Python 3.11 or newer; JSON Schema Draft 2020-12 via `jsonschema`; Python-Markdown for the optional local preview. No database, Node build, or framework is required.
- Keep all categories visible, including empty subcategories. Empty tables contain presentation placeholders generated by the renderer, never fake paper records.
- Tables sit under subcategories. The paper table header remains `Code`; repository links use GitHub icons with light/dark variants. Missing code is shown as `—`.
- Render newest year first, then venue/title/ID for stable ties. Preserve taxonomy order. Do not insert build timestamps.
- Validation is offline: schema constraints, stable ID uniqueness, known leaf references, duplicate paper identity, displayed-year consistency, survey placement, URL syntax, and template slots. It makes no claim about paper accuracy or URL availability.
- All contributed text is plain text. Rendering escapes Markdown/HTML metacharacters; URLs must be HTTP(S), without credentials or whitespace. Code and toolbox URLs must be GitHub repository URLs.
- Normal CI is read-only and offline after dependency installation. It validates, runs tests, and rejects stale README output; it never commits, opens issues, or edits data.
- Live link checks are explicit and bounded. Blocking/rate limits/timeouts are reported separately from confirmed HTTP errors; results never remove records automatically.
- Preview binds to loopback and serves only the generated catalog and intended documentation/assets. Its rendering approximates GitHub; GitHub remains authoritative for final display.
- Previous catalog/parser versions are retained in Git history. Editorial migration and abstract-review ledgers live in `data/curation/`; redundant historical copies and implementation plans are not shipped.

## Why this changes the earlier proposal

The previous idea of separate topic pages would duplicate the complete README layout now requested. One generated reader view is simpler. JSON provides editor support and exact schemas without requiring a YAML loader. Empty year files and per-category paper files are omitted: create a year file when a real entry needs it. Cross-cutting directories, separate benchmark/dataset resource sections, and a retrieval-system top-level category are intentionally absent from the agreed taxonomy.
